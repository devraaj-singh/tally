# Tally Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lean, good-looking, cloud-backed spending tracker (phone-first, installable) that logs expenses by category and shows a monthly overview.

**Architecture:** Next.js 16 App Router with Server Actions as the only backend. Postgres (Neon serverless HTTP driver) via Drizzle ORM holds categories and transactions. A single shared-password cookie gate guards all pages. UI is Tailwind + Framer Motion, phone-first, installable as a PWA. When `DATABASE_URL` is unset the app falls back to an embedded PGlite DB seeded with sample data so `npm run dev` works with zero setup.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS, Framer Motion, Drizzle ORM, `@neondatabase/serverless`, PGlite (dev fallback), `next/font` (Inter + Sora).

**Spec:** `docs/superpowers/specs/2026-11-22-tally-design.md`

## Global Constraints

- Single user; no multi-user, no accounts, no signup. Auth is one shared password (env `APP_PASSWORD`) → signed cookie.
- Free tier only; no paid services. Neon free DB in prod; PGlite fallback in dev.
- Phone-first responsive; must be installable to home screen (web manifest + icons).
- Money stored as integer **cents** (never floats). Amounts displayed with 2 decimals.
- Dates stored as `date` (no time) in the user's local sense; "this month" = calendar month of `today`.
- Deploys to Vercel; no step may require secrets at build time (DB init skipped during `phase-production-build`).
- Fonts via `next/font/google` (Inter, Sora) with `arial, system-ui` fallback stack.

## Review Focus

- **Empty state (no transactions yet):** overview shows $0.00 and an inviting empty message, not a broken chart or NaN. → covered in Task 7.
- **Deleting a category that has transactions:** must not orphan/crash; transactions reassign to an "Uncategorized" category. → covered in Task 3.
- **Wrong / missing password:** any page or server action without a valid cookie redirects to the password screen; a wrong password shows an error, not a 500. → covered in Task 4.
- **Amount input edge cases:** empty, 0, negative, non-numeric, >2 decimals → rejected with a message; valid input stored as exact cents. → covered in Task 3 (parse/validate) and Task 6 (form).
- **Month boundary / timezone:** an expense dated on the 1st or 31st lands in the correct month's total. → covered in Task 3 aggregation tests.
